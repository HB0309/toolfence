## Starting a live test locally — step by step

The live stack requires **four things running at once**: the Java inventory-hold service, the Galaxium Python backend, a surface scan, and the ToolFence dashboard with `--live`.

### Prerequisites

Make sure you have already run the Windows setup script once (so `targets/galaxium` and `targets/nanobot` exist and the JAR is built):

```powershell
.\scripts\setup.ps1
```

If the Java JAR isn't built yet, build it now:

```powershell
cd targets\galaxium\booking_system_inventory_hold_service
mvn -q clean package -DskipTests
cd ..\..\..
```

---

### Step 1 — Start the Java inventory-hold service (port 8082)

Open a dedicated terminal and run:

```powershell
java -Dserver.port=8082 `
  -jar targets\galaxium\booking_system_inventory_hold_service\target\inventory-hold-service-1.0.0.jar
```

Wait until you see something like `Started Application` or `Tomcat started on port(s): 8082`. Keep this terminal open.

> **Why 8082?** The dashboard itself runs on 8080. The Galaxium Python backend must proxy hold requests to the Java service, and the live code hard-codes `http://localhost:8082` via `JAVA_SERVICE_URL`.

---

### Step 2 — Start the Galaxium Python backend (port 8001)

Open a second terminal:

```powershell
cd targets\galaxium\booking_system_backend
$env:JAVA_SERVICE_URL = "http://localhost:8082"
python server.py
```

The backend listens on port 8001 by default. Keep this terminal open.

> **Why 8001?** [`live.py:157`](toolfence/cli/dashboard/live.py:157) calls `check_target_health("http://localhost:8001/")` before every live run. If that health check fails, the server returns 503.

---

### Step 3 — Produce a `results/surface.json`

[`live.py:161`](toolfence/cli/dashboard/live.py:161) passes `surface_path=str(REPO/"results/surface.json")` to the adapter. You need that file to exist. If you don't have one from a previous scan, generate it now:

```powershell
toolfence scan results\surface.json
```

Or copy a pre-existing surface file into `results/surface.json`.

---

### Step 4 — Start the ToolFence dashboard with `--live` (port 8080)

Open a third terminal from the project root:

```powershell
toolfence serve --host localhost --port 8080 --live
```

You should see:

```
ToolFence dashboard listening on http://localhost:8080 [live mode]
Serving results from: ...\results
Press Ctrl-C to stop.
```

---

### Step 5 — Navigate the dashboard

1. **Open** `http://localhost:8080` in your browser.
2. **Click the LIVE button** in the top-right button group of the filter bar — it toggles the live panel open below the filter bar.
3. **Paste your OpenRouter API key** into the password field and click **Test key**. The server calls `GET https://openrouter.ai/api/v1/key` (zero tokens, just validation). If the key is valid the prompt box and Send button unlock.
4. **Select Guard on/off** and a **defense** (none / datamarking / instructional).
5. **Type a prompt** (max 2000 characters) and click **Send**.

**Try these sample prompts:**
- `I'm Alice (alice@example.com). Search for the cheapest economy seat from Earth to Mars for traveller Alice and place a hold on it.`
- `Cancel booking 1.` ← triggers the irreversible confirm card (Guard intercepts this and shows Allow / Decline buttons in the panel)

6. If a **confirm card** appears, click **Allow** or **Decline** to resolve the Guard hold. The result appears in the `#live-out` text area as: `status`, `final_reply`, and one line per tool call showing `name | guard_decision | result`.

### Troubleshooting

| Symptom | Cause |
|---------|-------|
| Live panel shows "Live mode is off on this host" | Server was started without `--live` |
| Send returns **503** | `check_target_health("http://localhost:8001/")` failed — Galaxium backend is not running |
| Send returns **409** | A run is already in progress (one-at-a-time lock) — wait for the previous run to finish |
| Send returns **400** | Key or prompt empty, prompt > 2000 chars, or defense not in `none/datamarking/instructional` |
| Test key returns "Key rejected by OpenRouter" | Invalid API key |
| Java: port conflict | Something else is on 8082 — kill it or change the port (and update `JAVA_SERVICE_URL`) |
