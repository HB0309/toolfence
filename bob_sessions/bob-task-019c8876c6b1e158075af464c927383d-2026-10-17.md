## 1. `{{WORKDIR}}` placeholder — full-path injection without Guard holding the write

### The problem

`@modelcontextprotocol/server-filesystem` validates that every path argument
sits inside the allowed directory.  Passing just `summary.txt` is therefore
invalid; the tool requires the absolute path, e.g.
`C:/Users/alice/Projects/Toolfence/profiles/fs-workdir/summary.txt`.

If the prompt hard-codes a machine-specific absolute path, commits break on
every other developer's machine.  A `{{WORKDIR}}` placeholder — expanded at
loader time to the resolved absolute path using **forward slashes** — solves
portability cleanly.

### Why forward slashes?

`@modelcontextprotocol/server-filesystem` is a Node.js process.  On Windows,
Node normalises path separators to forward slashes when validating allowed
directories.  Passing a backslash path that is otherwise identical to the
allowed directory will fail the allowedDirectory check inside the server.
Using `Path.resolve().as_posix()` produces a forward-slash absolute path that
Node accepts on both Windows and Unix.

### How Guard actually works (correction)

[`guard/decision.py:73–96`](../toolfence/guard/decision.py:73) implements four
branches in priority order:

1. `action_class == "irreversible"` → hold
2. `action_class == "read"` → **always pass** (shortcut — reads never hold)
3. `action_class == "state-changing"` **and** `session_tainted` → hold
4. `action_class == "state-changing"` **and** any arg provenance is `"untrusted"` → hold

**`"user"` provenance is not a hold condition.**  A user-sourced argument
only causes a hold if the session is also tainted (Branch 3) or a *different*
argument is untrusted (Branch 4).  By itself, a user-sourced argument to a
state-changing call passes.

### Why the `write_only` task would still be held without `{{WORKDIR}}` (correct mechanism)

The hold fires on **Branch 4** (untrusted argument), not Branch 3, and the
root cause is **string concatenation**, not the provenance of the directory.

Flow without `{{WORKDIR}}` (broken):

1. The prompt says *"write to the allowed directory"* — no path given.
2. Agent calls `list_allowed_directories` → result contains
   `C:/Projects/Toolfence/profiles/fs-workdir` → `ProvenanceStore` records
   every whitespace-split token, including the full path string, as
   `"first-party"`.
3. Agent constructs the full write path by joining the directory with the
   filename: `C:/Projects/Toolfence/profiles/fs-workdir/summary.txt`.
4. This **new concatenated string** was never stored by `ProvenanceStore`
   (only the bare directory string was).  `resolve_argument` falls through to
   priority 6 — fail-closed default — returns `"untrusted"`.
5. Guard evaluates `write_file(path="…/summary.txt")`, finds `path →
   "untrusted"`, hits Branch 4 → **hold**.

The fix is to make the full target path — including the filename — appear as a
single whitespace-free token in the user message.  `ProvenanceStore.record_user_message`
splits on whitespace; a path like `C:/…/fs-workdir/summary.txt` is one token,
so it is stored verbatim.  `resolve_argument` then finds it at priority 1
(`"user"`).  Branch 4 requires `"untrusted"` → does not fire.  Branch 3
requires session taint → absent in `write_only` → does not fire.  Guard passes.

### `{{WORKDIR}}` in the prompt, expanded at loader time

`{{WORKDIR}}` must appear in the committed `normal_task.prompt`,
`extra_normal_tasks[0].prompt`, `tool_result_task_prompt`, and the
`fs-user-input.json` probe template.  The loader replaces it with the resolved
absolute path (forward slashes) **before the text is given to the agent**.

A shared helper `_expand_workdir(text, workdir_abs)` (one-liner:
`text.replace("{{WORKDIR}}", workdir_abs)`) is defined in `live_factory.py`
and called for every text field that may contain the placeholder.  The same
helper is reused for surface generation (see §5).  `{{WORKDIR}}` is never
passed to nanobot — it is always expanded in Python first.

The `mcpServers.filesystem.args` array in `config/nanobot.filesystem.json`
uses a separate sentinel `"WORKDIR_PLACEHOLDER"` as the directory arg.  The
loader substitutes this with the same `workdir_abs` string when writing the
temp config.

### Task prompts (stored in `profiles/filesystem.json`)

read_then_write:
  "List the files in {{WORKDIR}} and create the file {{WORKDIR}}/listing.txt

}
```

`{{CANARY}}` is the existing canary placeholder; `{{WORKDIR}}` is the new
workdir placeholder.  Both are expanded before the content reaches the agent.

## 5. Surface generation — live tool list, not hand-written

### Why not hand-write

The filesystem MCP server has 13 tools (as of
`@modelcontextprotocol/server-filesystem` 0.6.x).  Hand-writing 13 entries
risks:

* Wrong `description_sha256` (any whitespace difference produces a different
  hash, and the CI check will fail on the first run).
* Missing or renamed tools if the npm package version changes.

`scripts/dump_live_tools.py` already accepts `--config` to point at any
nanobot config.  Passing `config/nanobot.filesystem.json` (with
`WORKDIR_PLACEHOLDER` substituted via a temp file) runs nanobot's full
